动画制作要求：当前项目 Manim Community 0.21.0（以 worker 的实际环境探测为准），渲染器负责帧率、分辨率和导出。定义唯一顶层 GeneratedScene 类，可继承 Scene、ThreeDScene、MovingCameraScene 或自定义这些类的派生类。允许完整 Python、自定义 Mobject/Scene 辅助类、循环、ValueTracker、always_redraw、更新器、镜头与 Manim 变换，不受旧动作 DSL 限制。
必须 from aifs_media_runtime import media_step, load_context，在 construct 中 context = load_context()；它提供 request、approved_content、approved_models。不要调用 Scene.render()，不要改渲染输出目录、帧率或像素尺寸。worker 默认白色背景、深色文字；Text/MathTex 建议显式 color='#172033'，若自定义背景必须同步检查所有文字/公式/辅助线的对比，避免默认白字消失。中文使用 Text(..., font='Noto Sans CJK SC')；公式用 MathTex，使用只依赖 amsmath/amssymb/xcolor 的最小 TexTemplate（避免默认 physics 等未安装宏包），不要把中文塞进 MathTex。
先在 steps 编写可核对的分镜：每项只有 step_id、author_step_index（从0起）、caption（读者字幕）、observation（读者该看何处/何关系）、expected_change（真实可见前后变化）。step_id 用 ASCII 字母开头，只含字母、数字、下划线、连字符且最多64字符，例如 S1、S2-detail，与 worker 安全文件名规则一致。payload.author_step_mapping 逐项列出冻结作者步骤及索引，author_step_index 只能取 allowed_author_step_indices 和 output_json_schema 中枚举的值。按有独立教学意义的稳定状态组织 media_step，完整按顺序覆盖 request.animation.steps；同一作者步骤包含需要分别看清的不同教学观察时可拆分为子步，保留相同 author_step_index。原分式、必要的展开式、合并结果等承担不同推导作用的状态须分别清楚呈现并停顿，不能为少截几张图而省略中间推导，也不能在同一步中展示后清除全部必要中间状态、只把最终答案留在步末。不得省略、重排或把多个作者步骤合成无法定位的一步。initial_state、key_pauses、final_state 也必须实际呈现；额外收尾应并入或归属现有作者末步，不能创建新的作者索引。
每个制作步骤以 with media_step(self, 'S1'): 包住该步骤真正发生的 self.play(...) 与 self.wait(...)；step_id 必须与 steps 对应。多个 self.play、渐次出现、更新器运动可以放在同一个 with 中，随后让该步的教学状态真正落定并短暂停留。media_step 表示教学观察步骤，不是每个动画动作；不要仅因一次 play 或 wait 就增加步骤，也不要把无独立教学意义的过渡拆成子步。此粒度不限制自由 Manim 动作、循环、更新器或镜头能力。不得把实际动画放在步骤外再用空 with/零时长步骤冒充覆盖，也不要嵌套步骤。使用循环时每次调用仍须对应唯一的 step_id。时间戳由 worker 根据真实渲染时钟生成，不能由你填写。宿主从最终视频中提取这些步骤末端的真实画面用于审核，并保留真实步骤时间、字幕和文字稿；不要增加截图标记、时间字段或自行保存截图。
每步明确“看哪里—发生什么—为什么重要”，每次突出一个变化。对象先出现再变换；有推导依赖的变换顺序清楚，向量平移保持方向与长度等数学不变量。保留参照对象/旧状态让读者可比较，注意 Transform 后的对象身份与标签跟随。避免一次多处争抢注意力、持续转动镜头、过快飞入飞出或仅播放标题幻灯片。
动画也用于例题的代数推导：让读者看见一项从哪两个因子产生、条件允许哪一步、哪些项变号/消去/重组，不能把“代数内容”当成只播放公式幻灯片的理由。公式项与对应几何对象保持可追踪的颜色及标签；先建立对应，再变化，变化后回到原题。淡入、打字和换页本身不构成解释，至少要让请求中明确需要跟随的关系可见。中间运动只是过渡时，不能把它误说成每一帧都成立的数学映射；有限数值示意不冒充一般证明。
payload.example 提供原创的完整例题样例与独立 context：四项展开→辨认共轭交叉项→向量首尾相接看到虚部抵消→回到两倍实部。学习其对象身份、旧状态比较和公式/几何对应，不固定套用其主题、数值、三步数目或布局。源码适配本项目 Manim Community；网络上 Grant 的 manimlib、OldTex、旧式 CONFIG 或私有辅助类不能直接照搬。每次仍按当前 request 的步骤制作，不把样例步骤混入本题。
节奏应给读者真实观察时间：通常变换1至2秒、关键状态停顿1至2秒（复杂公式需更长），开头展示初态、结尾停留结论；按作者重点和内容调整，不用压缩时间掩盖缺步骤。动画的几何区域、标题/说明、公式区和字幕安全区需布局分离；保持参考系稳定、镜头移动有教学理由、关键对象始终在视框内。在电脑实际显示尺寸下，关键公式和对象标签保持清楚，标题及补充说明简短并小一层，详细解释由字幕和正文承担，不用大段大字遮住图形。宁可分步减少同屏文字；避免小字堆叠。检查最终 scale/arrange 后对象的实际屏幕大小：屏幕高度约 mobject.height / config.frame_height * display_video_css_height，等宽缩放的电脑显示换算由宿主显示策略注入。该换算用于核对实际大小比例，字形包围盒高度与字号门槛不是同一度量。不要先设大 font_size 再缩小整个 group 使字号失效；最终整体缩放、排布或镜头变化后必须重新检查可读性。

读者播放器默认逐步播放：点击某步，从该步 start 播到 end 后暂停，读者再选下一步，也可连续播放。因此每个媒体步骤末端应落在清楚、稳定、可单独观察的状态；将该步必要的变换、落定与短停顿放在同一个 media_step 内，不把关键结果放到下一步开头才出现。停顿时应停止需要落定的更新器、镜头或其他持续运动，不能只调用 wait 却让画面仍在变化。不要加模拟按钮或等待点击的 Python 循环；交互由 HTML 播放器完成，worker 仍制作普通 MP4 和真实时间信息。

caption 是播放器叠加在视频上的读者字幕，页面用 KaTeX 渲染：所有数学（变量、上下标、分式、积分、不等式、函数式）一律写在 `$…$` 内，例如 `$|z_n-z_0|<\delta$`、`$\mathrm{e}^{\mathrm{i}\theta}$`、`$\int_C f(z)\,\mathrm{d}z$`；中文叙述留在 `$` 外。不要在 `$` 外写裸 TeX（如 e^{iθ}、a_k、\frac{1}{2}），也不要用 Unicode 拼写公式代替。JSON 字符串里的反斜杠照常转义。
