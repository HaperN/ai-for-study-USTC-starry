# 图片批注：直接展示与本地识别两条可选路径

在“同学感悟”中选中教材位置后，点击“添加图片”或在编辑区域粘贴截图。支持PNG、JPG、静态WebP，每条最多3张、输入每张最多10 MiB、24百万像素、单边12000像素。可只发图片，不必写文字，更不必输入LaTeX。

每张图片独立选择：

- 直接显示图片：上传预览成功后即可发布，其他读者点击放大。
- 识别后发布：点“开始识别”，查看文字和公式预览，对照图片勾选核对确认后发布。发布后仍附有图片供对照。识别失败、结果截断、公式无法排版时，可切回图片方式。

原始分辨率保留，服务端会按EXIF转正并重新编码，去掉GPS/拍摄信息等元数据；JPEG质量95，PNG/WebP使用无损重编码。这里的“原图对照”指未经过OCR改写的图片内容，不表示逐字节保留相机原文件。暂不支持HEIC、PDF、GIF、SVG。

## 数据与权限

图片字节和识别候选保存在原SQLite数据库的新增annotation_images表。旧文字批注结构不变。未发布的图片只允许上传作者访问，发布时与批注在同一事务绑定并公开；不能使用其他作者、单元或版本的附件。删除整条批注会一起删除图片。未发布图片24小时过期，每作者在当前教材版本最多12张待发布附件。刷新后可点“未发布图片”，查看、恢复到当前小节的位置，或删除不再需要的草稿附件。文字草稿仍不提供跨页面关闭恢复。

上传幂等ID与发布请求ID分别保存，重试不重复生成同一记录。服务器不接受客户端声称的识别文本，只发布自己保存的完整候选；作者确认不代表系统已证明数学正确。昵称和学校认证沿用IdentityProvider，不以昵称判断图片权限。

## 本地识别配置

community命令增加两个可选参数：--ocr-python 指向已安装Torch/Transformers的独立Python，--ocr-model 指向已下载PaddleOCR-VL模型目录。两个参数一起使用；未配置时可以正常发图片，识别选项说明不可用。

本机复用了现有vision/vlm-venv和models/paddleocr-vl-1.6。识别进程有独立的生命周期守护：停止服务会结束模型进程，服务异常退出也会清理任务进程与临时图片。识别过程使用离线本地文件、trust_remote_code=False，不下载模型或访问外部AI服务。解释器路径保留虚拟环境链接，不能改成解析链接后的系统Python。当前实测设备为Apple Silicon/MPS；别的服务器需配置自己的运行环境。

每个服务同一时间最多运行一次识别，最长90秒，最多2048个输出token。模型按图片任务临时加载，完成后进程退出。文字/图片发布不依赖模型。识别是图片转写，不能当作自动解题或内容纠错。

## 接口

- POST /api/annotation-images：原始图片二进制，Content-Type为图片类型；需要X-AIFS-Unit、X-Upload-Request及既有身份/Origin/教材版本头。
- GET /api/annotation-images?pending=1：仅当前作者可列出本教材版本的未发布图片。
- GET /api/annotation-images/{id}：作者可读待发布图片，所有读者可读当前教材版本中已发布图片。
- DELETE /api/annotation-images/{id}：只能删除自己尚未发布的附件。
- POST /api/annotation-images/{id}/recognize：本人对待发布图片发起识别，结果会缓存且不自动发布。
- POST /api/annotations：新增可选images数组，每项是id、presentation（image或recognized）、confirmed。选择recognized必须已有完整服务端候选且confirmed为true。

前端只把识别结果中的数学分隔符交给现有KaTeX；其余内容按纯文本显示，不执行HTML。公式有长度、展开和数量限制；原始图片始终可查看。

## 环境与验证边界

图片处理依赖Pillow，可使用本项目community-images可选依赖安装。识别环境独立，不要求给主程序安装Torch。发布包不包含大模型权重、教材、用户图片或批注数据库。

本轮使用真实公式截图验证本地识别和两浏览器共享；没有拿学生真实手写样本做全面精度评测。模糊照片、草写符号和复杂推导都应由上传者对照图片核对，不确定时直接发布图片。

WebP画布和帧的尺寸在调用原生解码器前检查。未安装图片解码依赖时，上传入口明确显示不可用，文字批注和已有图片读取仍可使用。
